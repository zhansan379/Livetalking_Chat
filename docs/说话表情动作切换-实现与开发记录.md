# 说话表情动作切换 —— 实现与开发记录

> 本文档记录「数字人说话时按情绪切表情底座」这一功能的完整实现、踩过的坑与留给续开发的边界。基于 2026-08/09 的实际开发与联调，供后续再次上手时直接续接。

## 1. 目标与现状

让 LiveTalking 数字人在**说话的同时**带上情绪表情：LLM 每轮回答探测一个 `emotion`（如 sad/happy），渲染层把「说话的基地帧序列」整体换成对应表情底座视频的 cycle，口型照常贴脸生成。

- **粒度**：每轮一个表情（整段回答用一种底座，轮到边界回中性），不是逐句/one-shot 动作。
- **过渡**：进表情 / 回中性两处都做 ~0.3s 溶解过渡（`addWeighted` 渐变），不再一帧硬切。注：当前 sad 是海螺形象、与 `rem` 不同人，溶解观感为**两脸形变渐变**（morph）；若底座与说话形象同人，则是最自然的情绪渐变。溶解机制见 §3.1b。
- **现状**：功能代码已完整落地并修到稳定；当前只有 `sad` 一个表情底座（用户删掉了 happy/surprised，只保留 sad），已由「海螺委屈样例视频」生成。
- **设计依据**：`docs/动作视频作为说话基地帧.md` —— 换一套基地帧说话（而非 customopt 那种与说话互斥的抢插）。

## 2. 端到端数据流

```
浏览器说一句带情绪的话
  → agent/chat.py stream_llm_chat
      → _probe_tone（LLM 廉价探测，并发后台跑）输出 emotion 字段
      → datainfo['emotion']（顶层）
  → put_msg_txt(datainfo)  → TTS 随每个音频帧 eventpoint.update(**textevent)
  → AudioFrameData.userdata['emotion']
  → base_avatar.inference 批循环（推理线程）
      → 切底座 + 清队列 + index 归零  → set_emotion(emo)
  → inference_batch 用新底座 face_list_cycle 算嘴部 pred
  → process_frames.paste_back_frame 用同底座 coord/full 贴回 → 带表情且口型对位
```

## 3. 关键实现（按文件）

### 3.1 `avatars/base_avatar.py`（基地序列切换器）

- 状态成员：`self.emotion`（=`opt.emotion`，dict；`None`=功能关）、`_neutral_cycles`（各 cycle 成员→初值快照）、`_emotion_cache`、`_cur_emotion`、`_last_speech_ts`。
- `_CYCLE_ATTRS`：统一候选集合 `("frame_list_cycle","coord_list_cycle","mask_list_cycle","mask_coords_list_cycle","input_latent_list_cycle","face_list_cycle")`，各模型只存在子集；`cycle_attrs()` 返回实际存在的。
- `set_emotion(emotion)`：`None/neutral` 恢复 `_neutral_cycles` 快照；否则懒加载 + 缓存 `data/actions/<emotion>/`，按 `emotion.names` 校验。**功能开关关时静默返回。**
- **切换点（重要）**：情绪切换发生在 **`inference` 推理线程、算 `pred` 之前**（不是渲染线程），并在切换时：
  1. `_drain_res_queue()` 清掉用**旧底座**算出的在途预测；
  2. `index = 0` 新底座从头排帧；
  3. `set_emotion(emo)`。
  持续静音 >1.2s → `set_emotion(None)` 回中性。
- `_drain_res_queue()`：`get_nowait()` 清空 `res_frame_queue`。

### 3.1b 底座溶解过渡（进出表情，`process_frames`）

`process_frames` 维护 `_prev_emotion`（局部）与 `_last_out`（上一帧输出）。每当读到 `self._cur_emotion` 变化（＝底座刚被推理线程切换），就以 `_last_out` 为起点对当前帧做 `cv2.addWeighted` 渐变，时长 `_EMO_TR_DUR=0.3s`。切换后 `_drain` 已清队，`_last_out` 必然指向旧底座帧，方向正确。进出都触发（中性→sad、sad→中性各一次）。

### 3.2 三个子模型 avatar（wav2lip / musetalk / ultralight）

每个 `__init__` 尾部结构一致：
- `self._snapshot_neutral_cycles()` 快照默认基地序列；
- 声明 `self._load_cycle = lambda e, root='data/actions': load_avatar(e, root=root)`，返回各自需要的 cycle 成员 dict（也只有这些属性会被交换）。
- `load_avatar(avatar_id, root='data/avatars')`：把写死路径参数化为 `f"{root}/{avatar_id}"`（默认值不变）。
- 三个 `paste_back_frame` 都有**索引取模防御**：`xxx[idx % max(1, len(xxx))]`，防切换瞬间越界杀线程（正常同长无副作用）。

### 3.3 `agent/chat.py`（情绪注入）

- `_probe_tone(agent, message, emotion_names=...)`：LLM 探测同时输出 `emotion`；**候选由配置 `emotion.names` 动态生成**并动态校验——只放行 neutral 或名单内，防止探测出无底座的表情。
- `_probe_tone_into`：`emotion` 写到顶层 `datainfo.setdefault('emotion', ...)`；语气键仍写 `datainfo['tts']`。
- `stream_llm_chat` 触发条件：`emotion.enabled`（纯视觉，不绑 TTS 引擎）**OR** `doubao + doubao_tone.llm_tone`。并发 `asyncio.create_task` 后台填结果，不阻塞主回答。

### 3.4 `config.yaml`

```yaml
emotion:
  enabled: true
  names: [sad]                 # 候选表情（现只有 sad 有底座）
  sample_videos:
    sad: "D:\\...\\海螺_视频_做出委屈的表情，不说_550856995680083969 (1).mp4"
```
`config.py` 的 `_yaml_to_args` 会自动把嵌套 dict 变成 `opt.emotion`，无需显式 add_argument。

### 3.5 `scripts/prep_emotions.py`（样例视频 → 表情底座）

读 config.yaml 的 `emotion.sample_videos`，对每个表情调对应模型 `generate_avatar` 产出 `data/actions/<emotion>/`。**完成标记 = `coords.pkl` 存在则跳过**。内含三项「底座对齐说话形象」：

| 项 | 方案 | 对应函数 |
|---|---|---|
| 人脸裁剪尺寸 | 读说话形象 `face_imgs` 边长（本机 256），wav2lip 必须一致否则模型崩溃 | `_resolve_wav2lip_img_size` |
| 帧数 | 循环补齐到说话形象中性帧数（240） | `_neutral_frame_count` + `_pad_cycle_length` |
| 分辨率 | 样例视频下采样到说话形象 `full_imgs` 分辨率（本机 1280×720，LCD 填黑保构图） | `_align_video_resolution` |

外加 `--device cuda/cpu`（默认 cuda，本机请用 `--device cpu`，见 §5）。

## 4. 数据前提（重要，续开发必看）

样例视频必须与说话数字人**同一形象、同构图**，否则切表情瞬间会明显「换脸/换构图」。这是**数据硬伤，代码无法规避**。当前 sad 用的是**海螺 AI 生成**的视频，人物是否与 `rem` 同一角色模板**需肉眼确认**——不配就得换同形象委屈样例。

每个表情底座内部自洽（口型照常贴脸），但底座间的**几何一致性**（人脸位置/大小/分辨率/帧数）必须靠上面 §3.5 的 prep 对齐保证。

## 5. 本机坑与教训（务必先读）

1. **s3fd 人脸检测 GPU 假死**：本机 Windows 上 CUDA 跑 s3fd `batch>1` 会卡死不产出（测量：GPU batch16 挂死；CPU batch16 ≈26s/批，200+ 帧 3~4 分钟稳定跑完）。所以**生成底座请固定 `--device cpu`**，智能体写默认 `cuda` 但本机别用。别被「正常生成形象能成」误导——那条检测路径不等于本机的 batch 检测可靠。
2. **wav2lip 人脸尺寸必须等于模型输入尺寸**：`inference_batch` 直接把 `face_list_cycle[idx]` 喂模型、不做缩放。底座 `face_imgs` 若 ≠ 说话形象（如 96 vs 256），模型下采样后 conv(4x4) 打在没有 4x4 的 feature 上 → `RuntimeError: padded input size (2x2), kernel (4x4)`。
3. **表情底座帧数必须与中性一致**：推理线程启动只取一次 `length`，据此给队列编 `idx`；`set_emotion` 换上来一个更短的列表 → `list index out of range` **杀死渲染线程**。必须 pad 齐（§3.5）+ 运行时取模防御（§3.2）。
4. **切换要在推理前定底座**：每次情绪/底座切换必须发生在 `inference` 算 `pred` **之前**并清队列，否则「预测用旧底座算、贴回用新底座」→ 人脸位置错位。**不要**把切换挪回渲染线程。

## 6. 部署 / 复测步骤（当前状态）

```bash
python scripts/prep_emotions.py --device cpu     # 重建表情底座（现只有 sad）
python app.py --avatar_id rem                    # 注意：实际形象目录是 rem
```
浏览器说句委屈的话，期望日志：`emotion: switch -> sad(base frames=240)`（说话切底座、口型照常）→ 静音后 `emotion: reset -> neutral`。重点肉眼确认：**切 sad 那一瞬人脸不错位、且海螺人物与 rem 构图配得上**。

## 7. 待办 & 未决（续开发入口）

- [ ] **doubao TTS 403**：WS 握手被服务端拒回 403（凭证/接口/账号权限问题，与本功能无关），现靠 edge TTS 兜底。要恢复豆包音色需核对 `tts/doubao.py` 的 WS 地址与鉴权（appid/token/voice）。
- [ ] **config `avatar_id` 过期**：写的是 `wav2lip256_avatar1`，实际目录是 `rem`，建议改正，否则每次启动要 `--avatar_id rem` 覆盖。
- [ ] **恢复更多表情**：要加回 happy/surprised/angry，把 `emotion.names` 与 `sample_videos` 补回并 `prep_emotions.py --device cpu` 重建。当前 `names=["sad"]` 时探测器只在 sad/neutral 间选。
- [ ] **「表演式」情绪（未来功能）**：当前是「情绪基调（状态）」，整轮保持该表情，进出有溶解过渡但并**没有「情绪本身随演绎推进」**（委屈→渐松的表演弧）。若想要 one-shot 表演且能边说边演，需在此底座开关之上再做多段表情序列拼接，超出当前范围。
- [ ] 开发机**出网受限**（仅清华 pip + ModelScope 可达）——新增模型/依赖注意来源。
