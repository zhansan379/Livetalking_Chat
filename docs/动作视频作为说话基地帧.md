# 动作视频作为「说话基地帧」：边动作边说话的设计方案

> 状态：**设计方案（未实施）**
> 目标：让数字人在播放动作编排的同时，仍能对 TTS 语音对口型说话。
> 结论一句话：把"上传的动作视频"在线下渲染成基地帧序列、逐帧存好脸框坐标/mask/latent，说话时复用现有的"生成脸 + 贴脸"管线把脸贴到动作帧上，即可既走手势又不失语音。动作从"抢占插播"变为"换一套基地帧说话"。

---

## 1. 背景：为什么当前"动作编排时无法同时说话"

"动作编排"即 `customopt` 配置（`app.py:90`、`server/routes.py:137`）。每个条目是一个动作剪辑：`audiotype`（触发键）＋ `imgpath`（动作逐帧图）＋ `audiopath`（自带音轨）。触发走 `POST /set_audiotype → set_custom_state()`，仅前端/外部调用，agent 不触发。

当前在**三个环节**上，动作态都把正常说话顶掉了：

| 环节 | 代码位置 | 动作态行为 |
|---|---|---|
| 音频入队 | `avatars/audio_features/base_asr.py:59` | `get_audio_frame` 在动作态（`custom_audiotype>1`）只播 `audiopath`，不读 TTS 队列 → 动作态无语音 |
| 推理驱动 | `avatars/base_avatar.py:396-407` | 动作帧 `type>1` → `is_all_silence=True` → `inference_batch` 不跑 → `res_frame=None`，`paste_back_frame` 不执行 → 无对口型脸 |
| 画面渲染 | `avatars/base_avatar.py:458-462` | 走"全非 0"分支 → 直接取 `custom_img_cycle` 动作帧 → 不渲染说话内容 |

音频帧用 `type` 三态标注：`0=说话`、`1=静音`、`>1=自定义动作`。动作态把音频线和画面都独占，因此是**严格串行、互斥**的——动作播放期间既没有语音，推理也没产出说话脸。`flush_talk`（`base_avatar.py:197`）即便强制复位 `custom_audiotype=0`，也只是"打断动作、切回说话"，而非"叠加"。

## 2. 关键事实：普通说话本身就是"贴脸"

**模型从未重新生成全身，只重新生成脸部一块，再贴回基地全身帧。** 这是整个方案能成立的前提。

普通（无动作）对口型的完整配方（musetalk 为例）：
- `inference_batch(index, audiofeat_batch)`：把当前 TTS 的 Whisper 特征 ＋ 基地帧 latent 喂进 U-Net，`vae.decode_latents` 只解出**一张脸大小的 patch**，不产全身。
- `paste_back_frame(pred_frame, idx)`（`avatars/musetalk_avatar.py:155`）→ `get_image_blending`（`avatars/musetalk/utils/blending.py:96`）：
  ```python
  bbox = coord_list_cycle[idx]                 # 脸部框(x,y,x1,y1)
  ori_frame = frame_list_cycle[idx]            # 基地全身帧（身体/姿势/呼吸）
  res_frame = cv2.resize(pred, (x2-x1, y2-y1)) # 生成脸缩放到 bbox 尺寸
  face_large = body.crop(crop_box)             # 取脸周围一块
  face_large.paste(face, ...)                  # 新脸贴进该区域
  body.paste(face_large, ..., mask_image)      # 软 mask α 叠加回全身
  ```
- 基地帧序列 `frame_list_cycle`（身体姿势）＋ 每帧 4 件套 `mask_list_cycle / coord_list_cycle / mask_coords_list_cycle / input_latent_list_cycle` 在形象准备时一次性产出。

**基地帧承担姿势，脸是每帧按音频新生成、再无缝贴回。**

## 3. 核心思路：动作视频 →「另一套基地帧序列」

普通数字人 = 一段源视频 → 离线抽帧 → 每帧算出 4 件套 → 直播时生成脸贴回。给同一形象"多加一段动作基地序列"完全同构——复用现有准备管线即可：

### 3.1 离线准备（上传动作视频时做一次）

1. `ffmpeg` 抽帧 → 逐帧 PNG（与原形象画布同尺寸）。
2. `preprocessing.get_landmark_and_bbox`（`avatars/musetalk/utils/preprocessing.py:85`）→ `coord_list`（**逐帧脸框 = "存储其坐标"**）。
3. `get_image_prepare_material` 逐帧 → `mask_list` ＋ `mask_coords_list`（软 mask）。
4. musetalk 额外：逐帧 VAE 编码 → `input_latent_list`（U-Net 条件）。
5. 存到 `data/actions/<action_id>/`，按 avatar 注册。

### 3.2 在线说话（= 基地域切换）

- 动作激活 → 推理循环的"当前基地序列"从 idle `frame_list_cycle` 切到动作序列；帧数取 `len(动作序列)`，index 在动作区间 `mirror_index` 推进（与现有完全同款）。
- 每帧 `inference_batch` 用 `input_latent_list[动作idx]`，`paste_back_frame` 用 `coord_list[动作idx]` / `mask_list[动作idx]`，贴回 `frame_list[动作idx]` 这个动作全身帧。
- 动作播完 → 基地切回 idle。全程 TTS 不断，打断机制不用动。

## 4. 为什么这个方案同时干掉了两大难点

| 之前识别的难点 | 上一版方案的解法 | 本方案（基地帧）的解法 |
|---|---|---|
| 音频通道被动作独占 | 拆"音频出队/视觉特征"双通道 | 动作不再抢音频线、不配 `audiopath`，TTS 照常，`inference_batch` 照常由 type=0 驱动 → **无需拆通道** |
| 头部对齐（脸漂） | 动作限定"头部不动的手势" | 每个动作帧离线检测出**自己的** `coord_list/mask_list/crop_box`，`paste_back_frame` 按该帧自己的 bbox 贴 → 头怎么动脸贴哪，**对齐问题消失** |

`get_image_blending` 里的 `bbox`、`crop_box`、`mask` 全是 `[idx]` 逐帧取的，天然跟随动作帧的头部位置。

## 5. 落地代码改动（未实施）

代码瓶颈集中在：`paste_back_frame` 及 `inference_batch` 依赖的 `self.frame_list_cycle / coord_list_cycle / mask_list_cycle / mask_coords_list_cycle / input_latent_list_cycle` 目前是**写死成员**。改造为"从当前激活基地序列读取"（默认 = idle）：

1. 抽象一个基地序列选择器（如 `_base(attr, idx)`，内部按 `_active_seq` 指向 idle 或动作序列）。
2. 三份 sub-avatar（musetalk / ultralight / wav2lip）结构一致，改动点相同，可统一泛化。
3. 新增动作视频准备入口（服务器 API 或脚本），复用 `preprocessing.py` 与 `get_image_prepare_material`。

## 6. 残留注意点（不影响成立）

`inference_batch` 用该帧 latent 作为 U-Net 条件重建嘴部。普通手势（头保持大致正脸）无感；若某动作帧头部转到很侧的角度、或面部被手遮挡，相应 pose 素材无先例，贴出的脸可能轻微变形。对"上半身手势"类动作无碍；必要时可在该角度补数据增强兜底——非阻塞项。
