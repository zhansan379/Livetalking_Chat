# 对话打断与历史一致性（代际 supersede + TTS epoch + 立即落盘）

> 本文整理一次真实 Bug 的根因与三项修复的完整设计，供后续开发直接引用。
> 关联代码：`agent/chat.py`、`server/routes.py`、`avatars/base_avatar.py`、`tts/base_tts.py`。

## 一、背景问题

数字人实时对话里，ASR（含误听）、用户打断、LLM 后台流式回答、TTS 逐句播放并行发生。一个典型故障：

1. ASR 把"后端开发"误听成"投脑开发吧" → 模型开始回答 → **回合1 开始播音频**；
2. 用户打断，改口说"后端开发" → **回合2 开始**；
3. 现象 A：两个回答的音频**连在一起播**（叠读）；
4. 现象 B：`chat_history` 里 **"投脑开发吧"这条记录消失**（历史被覆盖）。

## 二、根因

把整个 pipeline 拆开看，问题出在两点：

### 根因 1：并发回合各自落盘 → 丢失更新
`/human` 的 chat 分支用 `asyncio.create_task(stream_llm_chat(...))` **fire-and-forget** 丢出去。每个回合各自 `ChatAgent(session_id)` 独立加载历史、各自 `save()`。

时序：
- 回合2 打开历史文件的时刻，回合1 还没把"投脑开发吧"写盘 → 回合2 内存历史里没有它；
- 回合2 结束落盘 → 用一份**不含回合1 记录**的完整历史**整体覆盖**了磁盘文件 → "投脑开发吧"永久丢失。

这是经典的 **并发 lost-update**，不是删除逻辑问题。

### 根因 2：停嘴不彻底 → 叠读
- **打断那个回合还在后台流式生成**：`flush_talk()` 每次只清了"此刻队列里已有的句子"，可回合1 的 LLM 还在断断续续吐 token，`stream_llm_chat` 会在 flush **之后**继续往 TTS 队列续塞新句子；
- 于是 turn1 残余 + turn2 新句首尾相接，`process_tts` 按先入先出连播 → "两次回答连起来"。

> 补充：TTS provider 各自在 `while ... and self.state == State.RUNNING` 里已能识别 PAUSE 立即截断**正在合成的一句**——这部分本来有效。真正漏掉的是"flush 后又续喂的句子"和"还没出队的旧句"。见 §四。

## 三、既有 VAD 打断（前端）

**有**，但只在前端，且它管不到后端续喂。

- `web/avatar-chat.html`：浏览器内 **Silero VAD**（ricky0123/vad-web，`lib/` 本地离线）。
  - `onSpeechStart` → 数字人正在说话时用户开口 → `interruptAvatar()` → `POST /interrupt_talk` → 服务端 `flush_talk()`；
  - 每条 `sendChat` 都带 `interrupt: true`，`/human` 里先 `flush_talk()` 再开新回合。
- 结论：**VAD 负责"知道该打断"；后端负责"打断后真的停得住、且历史不被旧回合覆盖"。** 本次三项修复补的就是后端这层空挡。

## 四、三项修复

### 修复 1：对话代际 supersede（会话级串行化）

**思路**：给每个回合发一个递增序号 `gen`，全局只认当前最大序号是"活着的回合"，小于它的都是 **stale（过期）**。stale 回合在**喂料前**和**落盘前**自检，发现过期就整体放弃。

**为什么用序号而不是直接 `task.cancel()`**：
- `cancel()` 是协作式的，只在 `await` 点生效，跨不过一行同步的 `agent.save()`，且时机有竞态；
- 序号是**可比较的无副作用值**——取消来不及生效时它兜底（旧回合到喂料/落盘处一查 `is_stale` 就放弃）。

代码 —— `avatars/base_avatar.py`：

```python
# __init__ 里
self._chat_gen = 0
self._chat_task = None

def begin_chat(self) -> int:      # 每开一轮 +1，返回给这一轮
    self._chat_gen += 1
    return self._chat_gen

def is_stale(self, gen: int) -> bool:   # 我的号 < 当前 → 被取代
    return gen < self._chat_gen

def attach_task(self, gen, task):   # 记录回合 task，并取消上一个未完成的回合
    prev = self._chat_task
    if prev and gen > 0 and not prev.done():
        prev.cancel()
    self._chat_task = task
```

代码 —— `server/routes.py`（`/human` chat 分支）：

```python
gen = avatar_session.begin_chat()
task = asyncio.create_task(
    stream_llm_chat(avatar_session, sessionid, params['text'], datainfo,
                    trace_id=params.get('trace_id'),
                    upload_note=params.get('upload_note'),
                    gen=gen))
avatar_session.attach_task(gen, task)
```

代码 —— `agent/chat.py`：`stream_llm_chat` 新增 `gen: int = 0` 参数，在所有喂料点 / 落盘点前自检：

```python
# 工具路径的喂料
_feed_talk(avatar_session, final, datainfo, gen)   # 同理 fallback、流式路径
# 流式逐句喂料：is_stale → 置空并 break
# 落盘前整体放弃
if gen and hasattr(avatar_session,'is_stale') and avatar_session.is_stale(gen):
    reply = None
if not (gen and hasattr(avatar_session,'is_stale') and avatar_session.is_stale(gen)):
    agent.save()          # stale 回合不写盘，避免覆盖新回合
```

> `gen=0` 时（如 `agent/reminder.py` 调 `_feed_talk` 不传 gen）跳过代际检查，提醒/定时任务照常，不受影响。

### 修复 2：TTS epoch（flush_talk 真正停嘴）

**思路**：给 TTS 队列项打上"入队时的代际"；`flush_talk()` 自增代际并清队；`process_tts` worker 只处理"代际 == 当前"的项，旧代际项直接丢弃。

代码 —— `tts/base_tts.py`：

```python
# __init__
self._epoch = 0

def flush_talk(self):
    self._epoch += 1
    self.msgqueue.queue.clear()
    self.state = State.PAUSE

def put_msg_txt(self, msg, datainfo={}):
    ...
    self.msgqueue.put((msg, datainfo, self._epoch))   # 打当代际

def process_tts(self, quit_event):
    while not quit_event.is_set():
        try:
            item = self.msgqueue.get(block=True, timeout=1)
        except queue.Empty:
            continue
        msg = (item[0], item[1])
        if len(item) >= 3 and item[2] != self._epoch:  # 旧代际 → 丢
            continue
        self.state = State.RUNNING
        self._run_tts_observed(msg)
    ...
```

> `flush_talk` 之后由新回合 `put_msg_txt` 打上"当前 epoch"，所以新句能过、旧句全丢——真正做到打断即停、不残留。

### 修复 3：用户消息立即落盘

**思路**：`add_user_message` 后立刻 `save()`，而不是等整轮 LLM 走完。这样：

- 即使本回合中途被打断/被取代，用户输入也已落盘；
- 配合修复 1：被取代的那个回合（turn1 的"投脑开发吧"）在 **turn2 打开历史文件之前**就已写盘 → turn2 加载时读得到它 → 最终历史不再丢。

代码 —— `agent/chat.py`：

```python
agent.add_user_message(message)
try:
    agent.save()          # 立即落盘，防打断即丢
except Exception as e:
    logger.exception("persist user message exception: %s", e)
```

## 五、三项修复的协同关系

| 措施 | 解决 | 关键链条 |
|---|---|---|
| 代际 supersede（#1） | 叠读 + 旧回合覆盖历史 | turn2 升位后 turn1 不再喂音频/写盘 |
| TTS epoch（#2） | flush 后残留不播 | 新回合 flush → 旧句全丢 |
| 立即落盘（#3） | 误听输入不丢 | turn1 先写盘 → turn2 加载得到 |

一句话：**VAD 决定"该打断"，代际决定"谁有资格说话"，epoch 决定"残留句别播"，立即落盘决定"输入别丢"**——四者合起来让"打断"真正干净。

## 七、后续开发注意（约定）

1. **新增喂料点**：任何调用 `avatar_session.put_msg_txt` / `_feed_talk` 的路径，必须拿到 gen 并做 `is_stale` 自检，否则打断后又会产生叠读。
2. **新增落盘点**：写历史前必须 `is_stale` 自检，否则并发回合会 lost-update。
3. **`stream_llm_chat` 的 `gen` 参数**：已有默认值 0（= 不参与代际），外部普通回调可忽略；但**会话级对话**必须从 `begin_chat()` 取值并回传。
4. **别用 `task.cancel()` 当唯一手段**：它只是锦上添花，正确性靠代际数值兜底。
5. **TTS 队列项现在是 3 元组** `(msg, datainfo, epoch)`：任何直接消费 `msgqueue` 的代码要兼容第 3 个元素（`process_tts` 已拆回 2 元组再下传）。
