# 摄像头「看用户」工具

数字人通过 agent 工具 **按需看一眼正在对话的用户**：抓一帧摄像头画面，交给后端的视觉模型（VLM）描述用户当前状态（情绪/表情、动作、穿着、环境），把描述作为工具结果回填给对话主模型，让数字人能围绕「你」此刻的状态自然回应。

## 时序与架构

画面以 **base64 JPEG 文本帧走一条专用 WebSocket**（`/api/camera/ws?session=<会话id>`），按需一帧一帧传，不做连续视频流。

```
浏览器 avatar-chat.html                      后端 agent 工具
┌─────────────────────────┐  /api/camera/ws   ┌────────────────────────────┐
│ 「摄像头」按钮 + 🔴指示灯     │ ◄─── WebSocket ───► │ agent/camera.py            │
│ getUserMedia 视频流          │（点开开关时建立）    │   CameraService(按 session) │
│ 收 capture_request → canvas │  ── snapshot ──►   │   request_capture 推送并等待 │
│ 缩放→JPEG→base64 回传        │                  └────────────┬───────────────┘
└─────────────────────────┘                                 │ 最新帧
                                                    ┌────────▼───────────────┐
                                                    │ tool look_at_user():    │
                                                    │  请求新帧(超时3s降级)     │
                                                    │  → async_call_vlm(图片)   │
                                                    │  描述用户 → 文本回填主模型  │
                                                    └──────────────────────────┘
```

### WebSocket 生命周期

| 阶段 | 触发 | 行为 |
|---|---|---|
| **建立** | 用户点开「摄像头」按钮，且 `getUserMedia` 拿到视频流 | `camWSLoop()` 同步 `new WebSocket('/api/camera/ws?session=…')`；成功后**常驻不关** |
| **会话重绑** | WebRTC 握手完成后真实 session id 落到页面 | 先 `close()` 旧 WS，再用真实 id 重连，避免绑在初始 `"0"` 上 |
| **断线** | 网络抖动/服务端重启 | `onclose` 里若开关仍开，1.5s 后自动重连 |
| **关闭** | 用户再点一次按钮 | `stopCamera()` → 停流 + `camWS.close()` + 熄灭指示灯 |

服务端**无法主动建立**这条连接，必须浏览器先连上来；数字人要看时经它推 `capture_request` 去「约」一帧。

### 消息协议

- 服务端 → 浏览器：`{"type":"capture_request"}`
- 浏览器 → 服务端：`{"type":"snapshot","data":"data:image/jpeg;base64,…"}`

## 配置

```yaml
tools:
  look_at_user:
    enabled: true   # true→数字人可点摄像头「看你一眼」
```

## 隐私设计

- 画面**按需抓取、即取即弃**：只在工具 handler 内部转成 data URL 喂给视觉模型，随后 GC；不进对话历史、不落盘。
- 前端**默认关闭**：点开开关才 `getUserMedia` 静默开流；本地不现实时画面；关闭即停流断 WS。
- 底部**红色脉冲指示灯**常显「摄像头已开启」，让用户始终知道自己正在被可能查看。
- 拿不到画面（未授权/未连接/超时）时工具如实返回降级话术，**不伪造、不阻塞对话**、不反复强求。

## 工具参数

`look_at_user` 支持一个可选参数 `instructions`，由对话主模型在调用时传入，用来**指定这一次让视觉模型专门分析哪方面**；留空则走默认的整体状态描述。

```json
{ "instructions": "用户的情绪是否开心？手里拿着什么？周围环境是否整洁、光线如何？" }
```

实现上：`instructions` 会被拼进给 VLM 的提示词（`agent/camera.py` 的 `look_at_user`），VLM 只按该关注点作答，并把可观察结果回填给主模型。配合示例：用户说「你看看我这样行吗」→ 模型可传 `instructions:「帮我描述一下我现在穿得是否得体」`。

## 使用前提与限制

1. **视觉模型需支持图像输入**：后端用 `LLM_ROUTING.vision` 配置的模型描述画面。若该模型不带图像能力，工具会降级为「我看到你了，但说不上来状态」——需把 vision 换成支持图像的多模态模型。
2. **必须有浏览器端开着开关并授权**才有画面；纯文本会话/未授权时返回「看不到」。
3. 摄像头通道**按 session 绑定**：工具定位到当前对话的会话，多会话互不串扰。
